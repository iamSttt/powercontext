# 一页技术说明：SDD 上下文管理系统

## 1. 模块结构

```
任务描述 ──► context_module.cli context
                 │
                 ├─ seekdb（minimax_sdd.sdd_documents，IK 全文索引）
                 │     检索：规格(spec) → 代码(code) → 测试(test)，返回真实路径
                 │
                 ├─ PowerContext（/v1/context/prepare）
                 │     读取上一轮保存的任务进展（跨进程复用）
                 │
                 └─ 组装上下文 ──► MiniMax-M3.1-Flash ──► 代码修改
                                        │
                                        └─ PowerContext(/v1/memory/remember) 保存本轮状态
```

模块入口：`python -m context_module.cli {index|context|state save|state load}`，输出为 JSON/文本，
包含每条资料的 `kind / path / title`，可直接核对来源。

## 2. 上下文选择方式

1. **索引**：遍历 `specs/*.md`、`business/library/*.py`、`business/tests/*.py`，按文件写入 seekdb，
   建 IK 中文全文索引；重复索引使用 `REPLACE INTO`，天然支持规格更新后的重新导入。
2. **检索**：任务文本直接作为查询，`MATCH(content) AGAINST(...)` 走 seekdb 全文检索；
   无命中时回退到关键词 `LIKE`，保证空结果可控。
3. **排序与组装**：按 spec → code → test 的优先级重排，保证「先约束、后实现、再验证」的上下文顺序。
4. **增量感知**：`spec_update_demo.py` 演示规格变更 → 重新索引 → 检索结果立即反映新内容
   （更新前 0 命中，更新后 1 命中）。

## 3. 各项技术的分工与证据

| 技术 | 实际承担 | 证据 |
|---|---|---|
| seekdb | 工程资料存储与检索：5 份资料、IK 全文索引、`MATCH...AGAINST` 查询 | `records/seekdb-evidence.txt`、`records/spec-update-evidence.txt` |
| PowerContext | 任务状态：`context_built` → 新进程 `state load` 返回 `status: ready`；`tests_passed` 同样可召回 | 验证样例步骤 3/4；`records/minimax-development-record.md` 记录状态写入 |
| MiniMax | 依据检索到的规格/代码/测试生成 `list_loans` 的 `status` 筛选实现（8.2s，3472 tokens） | `records/minimax-development-record.md`、`records/minimax-output-loans.py`、`records/code-diff.patch` |

## 4. 代码修改有效性

- **修改前**：`pytest business/tests` → `5 failed, 5 passed`（目标测试因缺少 `status` 参数失败，回归测试通过）
- **修改后**：`10 passed`（5 个目标测试 + 5 个回归测试全通过）
- 目标测试与回归测试在修改前后**保持一致**，未修改测试文件或断言。

## 5. 关键设计取舍

- **不引入 embedding**：MiniMax 当前 Key 不含 embedding 权限；使用 seekdb 原生 IK 全文检索即可满足
  「检索结果用于构造上下文」，同时减少外部依赖，评审可完全离线复现（仅 MiniMax 调用需要网络）。
- **状态与检索分离**：seekdb 存「工程资料」，PowerContext 存「任务进展」，各自职责清晰；
  模块重启后先 `state load` 再 `context`，实现跨会话续做。
- **可复现**：所有记录（提示词、响应、token、测试输出、差异）落在 `records/`，评审可按验证样例逐步重放。
